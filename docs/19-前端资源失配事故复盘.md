# 19 · 前端资源失配事故复盘（页面「变了个样子」）

> 现象：2026-11-08 用户打开 http://127.0.0.1:13000 发现页面与设计不符（全站无样式）。
> 结论：**不是设计被改动，而是 CSS 整份取不到，页面退化成裸 HTML。** 根因是构建产物与运行进程错配。

## 1. 现象与直觉误判

用户观感是「页面变了个样子」。第一直觉会怀疑：设计被改、组件被替换、主题被切。但逐项核对后，**源码与设计规范一字未动**。

## 2. 真实诊断过程（全部可复现）

```bash
# ① HTML 引用的 CSS 与实际磁盘产物对比
$ grep -o '/_next/static/css/[a-z0-9]*\.css' home.html
/_next/static/css/ca5872947eb3eb0a.css      ← HTML 引用
$ ls web/.next/static/css/
1c2f5d6041a7ba71.css                        ← 磁盘实有

# ② 该 CSS 的真实 HTTP 响应
$ curl -o /dev/null -w '%{http_code} %{size_download}\n' \
    http://127.0.0.1:13000/_next/static/css/ca5872947eb3eb0a.css
400 1987                                     ← 取不到（Next 对未知静态路径返回 400）

# ③ 构建与进程时间对比（决定性证据）
$ ps -o lstart= -p 87412
Sat Nov  7 23:57:13 2026                     ← next-server 启动
$ stat -f '%Sm' -t '%Y-%m-%d %H:%M:%S' web/.next/BUILD_ID
2026-11-08 00:24:14                          ← .next 被重建
```

`next-server` 在启动时把 build manifest 读进内存。**在它运行期间替换 `.next` 目录**，旧进程会继续输出引用旧哈希资源的 HTML，而这些文件已被新构建删除 → 全站 CSS/JS 404。

## 3. 根因

在**未停止**前端进程的情况下执行了 `npm run build`（为开启 `output: "standalone"` 并传入 `LLM_HUB_BACKEND_ORIGIN`），随后没有重启前端服务。等价于「引擎运转中换掉了零件目录」。

## 4. 修复

```bash
pkill -f next-server
cd web && LLM_HUB_BACKEND_ORIGIN=http://127.0.0.1:18700 nohup npm start -- -p 13000 &
```

修复后核验：57/57 静态资源命中，`RESULT: ALL_ASSETS_OK`。

## 5. 防复发机制（已落地）

| 机制 | 文件 | 作用 |
|---|---|---|
| 资源一致性守卫 | `verify/web_assets_check.sh` | 对 HTML 实际引用的**每个** `/_next/static` 资源做磁盘 + HTTP 双重校验；并直接比较「进程启动时间 vs 构建时间」，失配即报错退出 |
| 前端安全重启 | `deploy/web-restart.sh` | 原子流程：先停旧进程 → （可选）构建 → 启动 → 立刻跑守卫；杜绝错配 |
| 一键验收纳入 | `verify/full_acceptance.sh` | 新增 `web_assets_check.sh` 检查项 |
| 运维手册 | `docs/10-运维手册.md` §7 | 补「页面变样／全站无样式」故障行与诊断命令 |

## 6. 顺带发现并修复的两个真实缺陷

1. **bash 3.2 多字节变量名解析**：macOS 自带 bash 3.2 会把紧跟 `$VAR` 的中文字节并入变量名，`echo "$SERVER_PID（…）"` 报 `unbound variable`。已对 `deploy/*.sh`、`verify/*.sh` 统一改用 `${VAR}` 显式界定。
2. **字体离线降级未文档化**：`fonts.googleapis.com` 在此环境不可达（实测 8s 超时、HTTP 000），品牌字体回退到系统字体栈。这属预期降级（`--font-sans` 已含 `ui-sans-serif/system-ui/PingFang SC/Microsoft YaHei`），已写入运维手册。

## 7. 经验

- **构建产物与运行进程必须配对**。任何 `npm run build` 之前先停服务，或直接用 `deploy/web-restart.sh`。
- **「外观变了」先查资源加载，不要先查设计**。一条 `curl -o /dev/null -w '%{http_code}'` 就能定性。
- **时间戳是最快的判据**：进程启动时间 < 构建时间 ⇒ 必然错配，无需逐字节比对。
