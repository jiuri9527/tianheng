## 2. 威胁模型

### 2.1 资产与信任边界（依据 `LLM-API-Aggregator-Prompt.md`）

| 资产 | 依据 | 价值 |

| JWT access/refresh、用户口令哈希 | `:41`、`:101` | 高：越权、接管账号 |
| `MASTER_KEY`（AES-256-GCM 主密钥） | `:90`、`:184` | 最高：泄露即所有渠道密文可解 |
| `request_logs`（含完整输入输出） | `:25`、`:106` | 高：含用户提示词与响应 |

| 上游响应（`/models` 清单、chat 响应、SSE 流） | `:45-52`、`:62` | 中高：不可信输入，注入载体 |
| 可用性与连接池/调度器 | `kernel/contract.go:13-71`、`:28` | 中高：DoS 面 |

信任边界：**B1** 匿名外网→数据面/管理面；**B2** 登录用户→渠道贡献面（`POST /api/channels` 提交 `base_uri`+`api_key`+`custom_headers`+`models_path`+`chat_path`，服务端主动向该 URI 发请求）；**B3** 平台→上游出站（带上游 key）；**B4** 上游→平台入站不可信数据；**B5** 租户 A→租户 B 资源（按 id 读写渠道/令牌/日志）。

### 2.2 四类攻击者

**A. 外部攻击者（未认证 / 仅持无效令牌）** — 入口 B1。能力：任意 HTTP 请求/body/header、可控 `model`、可挂起 SSE 长连接。目标：绕过 `sk-` 校验（`:41`、`:82`）、伪造 JWT、撞库登录、未授权读 `/v1/models`。关注：认证绕过、注入、无界 body、SSE 无超时、连接池耗尽、错误信息回显。

**B. 恶意渠道贡献者（已登录低权用户）** — 入口 B2→B3。能力：控制 `base_uri`、端口、路径、自定义 header、上游响应内容（自建假上游）、SSE 帧内容。目标：把 `base_uri` 指向 `127.0.0.1` / `169.254.169.254` / 内网段 / DNS rebinding 域名；用 `custom_headers` 注入头；让平台把上游 key 发往攻击者服务器。关注：SSRF、上游响应注入、密钥回显、越权访问他人渠道。

**C. 越权租户（持合法 `sk-` 或普通用户 JWT）** — 入口 B1/B5。能力：合法凭据、可并发重复请求、可篡改请求参数中的 ID。目标：用他人 `channel_id`/`token_id` 读写；普通用户调 `/api/admin/*`；把配额刷成负数或溢出；绕过 `allowed_models[]` / `ip_allowlist[]`；并发双花配额。关注：IDOR/角色校验、JWT 实现、令牌比较是否常量时间、配额扣减原子性。

**D. 上游响应注入（恶意/被劫持上游）** — 入口 B4。能力：完全控制响应字节、状态码、header、SSE 事件序列。目标：超长/深层/畸形 JSON 打挂解码器；编造模型 id 污染全局池（违反 C-1）；SSE 帧注入；超长响应耗尽内存；注入日志控制字符；返回 NaN/负价格污染计费。关注：不可信 JSON、SSE 帧注入、日志注入、C-1 真实性校验。

## 5. 漏洞结论表（33 条，每条含编号/CWE/严重度/文件:行号/逐字证据/触发路径/影响/修复方案）

> 严重度：Critical > High > Medium > Low。所有补丁均为 `patches/NNN-*.patch`，路径正确、可 `git apply`（§9 真实校验）。

### V-01 [Critical] CWE-918 SSRF：出站客户端跟随重定向 + 拨号时重新解析 DNS，绕过 base_uri 校验
- **文件:行号**：`src/internal/channel/channel.go:113`（逐字 `if err := s.Validate(in.BaseURI); err != nil {`）；`src/internal/discovery/discovery.go:39`（逐字 `Doer: &http.Client{Timeout: 15 * time.Second},`）；`src/internal/relay/relay.go:63`（逐字 `Doer: &http.Client{Timeout: 180 * time.Second},`）；`src/internal/discovery/discovery.go:81`（逐字 `data, err := io.ReadAll(io.LimitReader(resp.Body, 16<<20))`）；`src/internal/discovery/discovery.go:197`（逐字 `return d.recordFailedProbe(m, fmt.Sprintf("上游返回 HTTP %d: %s", status, trunc(string(respBody), 300)))`）
- **触发路径**：贡献者创建渠道时用可控公网域名通过 `ssrf.Validate` → 之后把 DNS 改到 `127.0.0.1` / `169.254.169.254`（DNS rebinding），或让自建上游返回 `302 Location: http://169.254.169.254/latest/meta-data/iam/security-credentials/...`；默认 `http.Client` 自动跟随 3xx 且拨号时重新解析 → 请求落到元数据；响应体被 `trunc(...,300)` 写进 `ModelProbe.Error`，或 `SyncChannel` 把 `err.Error()` 写进 `channel.LastError`（`discovery.go:126`），经 `GET /api/channels` 回显给攻击者。
- **影响**：云元数据凭据泄露、内网服务探测、把渠道 `api_key` 所在请求导向攻击者控制的跳；F13 SSRF 防护整体失效。
- **修复方案**：`patches/011-ssrf-dialpin-and-redirect.patch` — 在 `ssrf` 包新增 `SafeClient(timeout, lookup)`：`DialContext` 在拨号瞬间解析并逐 IP 用 `isBlocked` 校验、固定已校验 IP 连接（消除 TOCTOU）；`CheckRedirect` 对每跳调用 `ValidateWithResolver` 并限制 3 跳；新增 `looksNumericHost` 拒绝十进制/八进制/十六进制 IP 字面量；`discovery.New` 与 `relay.New` 改用该客户端。保留 F2 自定义 base_uri 能力（内网 IP 全段拒绝比「非 80/443 内网端口」更严格）。
