## 0. 目标与结论

用户只填 `provider_type + base_uri + api_key + visibility`，站点用该密钥**实时**请求上游 `GET {base_uri}/models`，自动发现全部真实模型及其参数，并对每条模型做一次真实极小调用采集真实输入/输出样例；用户**不填任何模型名**。拉取失败时模型列表保持为空并标记 `probe_status=unavailable`，绝不填充占位/编造模型。

真实结论：8 个新增单测全部 PASS；全仓 `go build ./...` / `go vet ./...` / `go test ./... -count=1` / `tsc --noEmit` 全部 exit 0；新增代码中不存在任何硬编码编造模型 id（`grep_exit=1`），测试夹具所用 id 全部可在 `data/models-real.json` 逐字查到。

## 1. 数据流

```
用户提交 4 个字段
  → POST /api/channels（channel.Service.Create）
     ① SSRF 校验 base_uri（ssrf.Validate）
     ② AES-256-GCM 加密 api_key 落库，只回 key_hint
     ③ CreateChannel 成功后立即自动触发 AutoDiscover
  → discovery.AutoDiscover
     ├─ SyncChannel → fetchModels → GET {base_uri}/models
     │    · OpenAI 兼容：Authorization: Bearer <key>
     │    · Anthropic：x-api-key: <key> + anthropic-version: 2023-06-01
     │    · parseUpstreamModels：逐字解析 id/name/context_length/pricing/
     │      architecture/supported_parameters/top_provider，Raw 保留原始对象
     │    · 增量 upsert：复用模型 ID、保留已有真实探测样例、清理下线别名
     │    · 失败/空 data：DeleteModelsByChannel + probe_status=unavailable
     └─ AutoProbe（后台，独立 context，同渠道不并发重复）
          · 每条未探测模型一次真实极小 POST /chat/completions（或 /messages）
          · 记录真实输入、真实输出、prompt/completion tokens、延迟
          · 失败只标记 probe_status，绝不写入任何编造输出
  → 前端 GET /api/channels/:id 渲染真实模型表 / 参数卡片 / 真实输入输出样例
  → 刷新按钮：POST /sync-models + POST /probe + 重新 GET 详情
  → AutoRefresher 定时（MODEL_AUTO_REFRESH_SEC，默认 6h）对所有 active 渠道重复上述流程
```

```go
func (d *Discoverer) fetchModels(ctx context.Context, ch *store.Channel) ([]AutoModel, error) {
	cx, err := d.channelCtx(ch)
	...
	ad := adapter.ForProvider(ch.ProviderType)
	url, headers, err := ad.ModelsRequest(cx)
	...
	if isAnthropic(cx) {
		headers.Set("x-api-key", cx.PlainKey)
		ver := cx.APIVersion
		if ver == "" {
			ver = adapter.AnthropicVersion // 2023-06-01
		}
		headers.Set("anthropic-version", ver)
	}
	headers.Set("Accept", "application/json")
	status, body, err := d.do(ctx, http.MethodGet, url, headers, nil)
	...
	return parseUpstreamModels(body, status, isAnthropic(cx))
}
```

## 3. API 契约（不新增路由，全部复用既有端点）

| Method / Path | 鉴权 | 自动发现相关行为 |
|---|---|---|
| `POST /api/channels` | JWT | 只提交 `provider_type/base_uri/api_key/visibility`（+ 可选高级字段）；保存成功后自动同步 `/models` 并后台真实探测。响应含 `id`、`key_hint`、`models_discovered`、`connection_ok`、`connection_error`、`probe_status` |
| `PUT /api/channels/{id}` | JWT + 归属 | 更新成功后自动重新发现真实模型 |
| `GET /api/channels/{id}` | JWT + 归属 | `models[]` 为该渠道真实发现的模型，含 `raw_json`（逐字上游对象）、`probe_input`/`probe_output`/`probe_latency_ms`/`probe_prompt_tokens`/`probe_completion_tokens`、`probe_status`、`param_source=upstream` |
| `POST /api/channels/{id}/sync-models` | JWT + 归属 | 手动增量同步真实 `/models`，并后台补齐真实探测 |
| `POST /api/channels/{id}/probe` | JWT + 归属 | 手动对全部模型做真实极小探测 |
| `POST /api/channels/{id}/test` | JWT + 归属 | 返回真实发现结果：真实模型数量、真实 id 列表（消息文本）、真实延迟 |

统一错误体 `{"error":{"message","type","code","request_id"}}` 保持不变。上游不可达时 `/models` 列表为空、`probe_status=unavailable`，响应中不含任何编造模型名。
