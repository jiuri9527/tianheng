# 13 · 实时刷新监控面板与调用曲线（天衡）

> 所有人可见：无需 JWT、无需 sk- 令牌即可访问。数据 100% 来自真实 `request_logs` 聚合，**禁止编造任何数字**；无数据时返回全 0 且标记 `available:false` 的真实空态。

## 1. 架构与数据流

```
真实调用 ──► metering 写 request_logs（完整输入/输出/TTFT/tokens）
                │
                ▼
telemetry.Snapshot() 聚合（只读、加锁快照、绝不落明文敏感数据）
                │
                ├──► GET  /api/telemetry/snapshot   （public，完整聚合快照）
                └──► GET  /api/telemetry/stream     （public，SSE 每 2s 推送）
                                │
                                ▼
前端 /monitor 页面：EventSource 实时刷新 + 轮询兜底 + SVG 多曲线
```

- 聚合维度：总请求数、QPS、成功率、平均/最大 TTFT、prompt/completion tokens 总量、按 model / channel / provider / status 分组、最近 60 分钟每分钟时间序列 buckets。
- **只返回聚合数字**：绝不返回完整输入输出、api_key、sk- 令牌、JWT、密码哈希（`telemetry.go` 输出结构无任何原文字段）。
- SSE 头：`Content-Type: text/event-stream`、`Cache-Control: no-cache`、`X-Accel-Buffering: no`，逐块 `Flush()`；客户端断开时 `ctx.Done()` 立即结束。
- public 端点链：`middleware.Chain(RequestID, CORS)`——无 `Management`，任何访客可读。

## 2. 端点契约

| Method | Path | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/api/telemetry/snapshot` | public | 一次完整聚合快照 |
| GET | `/api/telemetry/stream` | public | SSE `data: {snapshot}` 每 2s 推送 |

统一注册（由 Lead 在 `buildMux()` 接线）：

```go
telemetry.Register(mux, s.St, s.Cfg, s.Auth)
```

## 3. 前端

- `web/app/monitor/page.tsx` — 监控页入口（OpenRouter 风格版式）
- `web/components/MonitorClient.tsx` — EventSource 实时订阅 + 断线轮询兜底 + 手动刷新
- `web/components/MonitorCharts.tsx` — 纯 SVG 多曲线（QPS / 成功率 / TTFT / token 消耗 / 按模型分布），零图表库依赖
- `web/components/MonitorTypes.ts`` — 与后端快照对应的 TS 类型

无数据时显示「暂无真实调用数据」空态，绝不画任何编造曲线点。

## 5. 真实端到端验证

在靶场/本地服务启动后（`deploy/target-range.sh start` 或直接 `go run ./src/cmd/server`）：

```bash
curl -s http://127.0.0.1:18400/api/telemetry/snapshot | python3 -m json.tool | head -30
curl -N http://127.0.0.1:18400/api/telemetry/stream   # 观察每 2s 一帧 data: {...}
```

无真实调用时 `available:false`、各计数为 0；产生真实调用（如无上游时 502 也会进入 request_logs）后 QPS/成功率/状态分布随真实记录变化。

## 6. 已知限制

1. SSE 依赖反向代理关闭缓冲（`deploy/nginx.conf` 已设 `proxy_buffering off`）。
2. 时间序列窗口固定最近 60 分钟，长历史请用 `/api/logs`。
3. 快照在锁内计算，数据量极大时（>10 万条日志）开销线性增长，后续可加分片缓存。
