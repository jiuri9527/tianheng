## 2. 发现的漏洞（本轮 2 条，均已修复复测）

### V-39 [High] CWE-770 — 单一来源两次高危探测即可把全站打成 423（可用性 DoS 放大）

- **发现过程（真实）**：offsec 攻击轮次 [D] 组第 2 条路径穿越探测后，靶场全部端点（含 `/api/rankings` 公开排行榜）立即变为 `423 firewall_lockdown`，正常用户完全不可用（`round3/08-v39-evidence.txt`）。
- **证据**：修复前 `src/internal/firewall/firewall.go` 的 `raise()` 中 `if sev == "critical" && rec.hits >= 2 && rec.score >= BlockScore { needLockdown = true }` —— 单台主机第 2 次 critical 探测即触发全局 lockdown + 数据封存，无视 `LockdownIPThreshold`。
- **危害**：攻击者用 **2 个请求**就能让全站对所有用户返回 423，把「自动保护」武器化成最廉价的 DoS。
- **修复**（`patches/022-firewall-single-source-no-global-lockdown.patch`，已应用）：全局 lockdown 只能由**多源协同攻击**触发 —— 需同时满足 ① 多个外部 IP 被封；② 被封数达 `LockdownIPThreshold`（强制 ≥2）；③ 回环来源不参与升级。单 IP 只做自身封禁（429，BlockTTL 内），其他用户不受影响。
- **复测**：`TestSingleSourceCannotTriggerGlobalLockdown` PASS（单源 6 次 critical → 自身 429，全站仍 200）；`TestLoopbackNeverEscalatesToLockdown` PASS。靶场实测：6 次路径穿越后 `level=throttle sealed=False blocked_ips=0`，`/api/rankings /api/telemetry/* /v1/models` 全部恢复 200/400/401/404 正常语义。

### V-40 [Medium] CWE-400 — 回环来源被 IP 封禁导致单机部署自锁

- **发现过程（真实）**：V-39 复测后，靶场（客户端即 `127.0.0.1`）自身被 `auto_ban_ip` 封禁 5 分钟，所有后续请求 `429`（`round3/09-v39-retest.txt`）。
- **危害**：单机 / 容器化 / 同机反代部署下，**唯一客户端就是回环** —— 一次探测等于把运维自己封 5 分钟，「攻击检测」变成「自我 DoS」。
- **修复**（`patches/023-firewall-loopback-never-banned.patch`，已应用）：回环来源不做 IP 封禁与全局升级，事件仍完整记录（`action=observe_loopback`），检测可见性不丢。
- **复测**：`TestLoopbackNeverGetsIPBanned` PASS（回环 8 次攻击 → 全部 200，事件仍记录，sealed=false）。
